Aturan Bisnis & RumusNotasi: FP harga asing per unit, SR sell_rate snapshot, CR cost_rate, fee fee per unit, qty jumlah.harga_jual_idr per unit = round_up(FP × SR, pembulatan_trip).total_item = (harga_jual_idr + fee) × qty. Item berstatus OUT_OF_STOCK bernilai 0 pada tagihan (nilai historis tetap tersimpan).subtotal_items = Σ total_item.total_tagihan = subtotal_items + ongkir − diskon.total_dibayar = Σ pembayaran sah (DP + pelunasan) − Σ refund yang dikembalikan.sisa_tagihan = total_tagihan − total_dibayar (negatif berarti kelebihan bayar).Profit item = total_item − (harga_beli_aktual_asing × qty × CR). Jika harga beli aktual kosong, pakai FP sebagai estimasi.Rincian profit: fee = fee × qty; selisih kurs = FP × qty × (SR − CR); selisih harga = sisanya (pembulatan, selisih harga beli aktual).Semua perhitungan dijalankan di service backend dalam satu transaksi database dan dihitung ulang setiap perubahan item/pembayaran/ongkir/kurs. Nilai total disimpan (denormalisasi) untuk performa, dengan pengecekan konsistensi harian.Refund otomatis (acceptance criteria #2): saat item → OUT_OF_STOCK, total tagihan dikurangi nilai item tersebut; jika total_dibayar > total_tagihan, order berstatus OVERPAID dan muncul tugas "Refund Rp X". Tidak ada baris pembayaran yang diubah.Order CANCELLED memiliki total tagihan 0 dan nilai historis disimpan pada snapshot.7. State MachineItem: PENDING → PURCHASED → ARRIVED; PENDING/PURCHASED → OUT_OF_STOCK. Pembalikan PURCHASED → PENDING diizinkan untuk Shopper dalam 10 menit (koreksi salah centang) dan selanjutnya hanya Owner/Admin. OUT_OF_STOCK → PENDING hanya Owner (barang ditemukan kembali) dan mencatat audit.Order: DRAFT → CONFIRMED → PROCESSING → SHIPPED → DELIVERED; CANCELLED dari status mana pun sebelum SHIPPED.PROCESSING otomatis ketika ada item pertama yang PURCHASED.SHIPPED mensyaratkan resi terisi dan tidak ada item PENDING.DELIVERED manual (atau otomatis bila ada setting).Trip: OPEN → SHOPPING → SHIPPING → COMPLETED.Setiap transisi tidak valid menghasilkan 409 Conflict dengan kode error INVALID_STATE_TRANSITION.8. Alur Pengguna UtamaPersiapan: Owner membuat trip (kurs, fee default) → status OPEN.Order masuk: Admin mencari/menambah customer → membuat order & item → kirim ringkasan invoice ke pelanggan → catat DP → order CONFIRMED.Belanja: Owner mengubah trip ke SHOPPING → Shopper membuka daftar belanja di HP → centang "Dibeli" atau "Kosong" → tagihan otomatis menyesuaikan.Penagihan: Admin melihat order PARTIAL/OVERPAID → catat pelunasan atau refund.Pengiriman: Admin input ongkir & resi → order SHIPPED → DELIVERED → trip COMPLETED.Evaluasi: Owner melihat dashboard profit per trip.11. (default: tidak ada; dapat ditambah sebagai biaya tambahan di v1.1)Lampiran A: Daftar Kode ErrorVALIDATION_ERROR, UNAUTHENTICATED, FORBIDDEN, NOT_FOUND, DUPLICATE_PHONE, TRIP_CLOSED, INVALID_STATE_TRANSITION, PAYMENT_ALREADY_VOID, LAST_OWNER_PROTECTED, DP_REQUIRED, RATE_LIMITED, INTERNAL_ERROR.Lampiran B: Contoh PerhitunganTrip Bangkok: SR = 465, CR = 452, pembulatan Rp 100. Item: harga 890 THB, qty 2, fee Rp 25.000/unit.Harga jual/unit = 890 × 465 = 413.850 → dibulatkan Rp 413.900Total item = (413.900 + 25.000) × 2 = Rp 877.800Modal = 890 × 2 × 452 = Rp 804.560Profit = 877.800 − 804.560 = Rp 73.240 (fee Rp 50.000 + selisih kurs Rp 23.140 + pembulatan Rp 100)Jika pelanggan sudah DP Rp 500.000 lalu barang kosong: tagihan menjadi 0, status OVERPAID, refund Rp 500.000, riwayat DP tetap utuh.
